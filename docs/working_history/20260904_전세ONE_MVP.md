## 리더 마감 수정 (경미 2건 해소)
경미 2건은 뿌리가 하나 — 절차형 데이터(stages·reject)에 항목별 `updated`가 없어 `stage.js:pickUpdated()`가 하드코딩 날짜(`'2026-09-04'`)를 씀(데이터 변경이 화면에 미반영되는 드리프트).

**계약 판정(리더 결정):** 절차형 데이터셋(stages·reject-track)은 하나의 큐레이션 문서이므로 **파일 단위 `updated`가 정본**이고, 항목별 `updated`는 두지 않는다. 항목별 `updated`는 자원(resources)·지역(regions)처럼 항목이 독립적으로 갱신되는 데이터셋에만 적용. → 계획서 §3 일반규칙("전 항목 updated")과 §3.2/§3.6 구체 스키마의 모순은 이 원칙으로 정리.

**코드 수정 (JSON 데이터 무변경 → `_bundle.js` 재생성 불필요):**
- `assets/js/data.js` — 로더가 파일 최상위 `updated`를 `_updated` 맵에 보존(fetch·bundle 양 경로) + `D.fileUpdated(key)` 접근자 추가.
- `assets/js/views/stage.js` — `pickUpdated()`가 `D.fileUpdated('stages')`를 사용(하드코딩 제거).

**검증:** 정적 서버(:8123) 실브라우저 확인 — `D.fileUpdated('stages')` = "2026-09-04", 화면 "확인일 2026.09.04" 데이터 기반 렌더, 콘솔 에러 0. F2 계산기 위험(90%) 신호등·링크아웃·하단 CTA 정상.
